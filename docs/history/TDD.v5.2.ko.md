## 1 판정 원칙과 범위 변경

최신 목적은 아카이브다. v4.0의 PKG 패키지·게시·variant·인공위성 분리·자동 대상 프로젝트 이행 사례는 보존본의 선택 후속으로 옮기고 현재 릴리스 필수/통과율에 넣지 않는다. 영상만 보이거나 파일 위치만 저장하면 현재 요구를 만족하지 않는다. 동영상·이미지 결과물과 모든 소스 유형을 보존하고 다시 확보할 수 있어야 한다.

캐시를 덜 저장한 수치만으로 통과시키지 않는다. 필요한 `.uproject/Content/Config/Source/Build/Plugins`·바이너리 예외·외부 자료·고유 Saved 자료가 계획대로 남아야 한다. 제외는 **보존본으로 복사하지 않는 것**이며 원본 파일 삭제를 허용하지 않는다.

테스트 중요도 B0는 원본 훼손·권한 노출·필수 자료 손실/잘못된 보존 완료, B1은 핵심 업무, B2는 보조 품질이다. 수준 U(단위), C(컴포넌트), I(실제 API/DB/파일/SMB/worker 통합), E(브라우저), UE(실제 등록 엔진)다. checksum 완료·미리보기 ready·프로세스 종료·실제 UE 열기 통과는 별개이며 mock 성공으로 대체하지 않는다.

## 2 실행 환경·fixture

운영 NAS/원본을 복제·익명화한 전용 공유·DB·원본/아카이브/임시/복원 경로를 사용한다. 운영10TB 자료에서 장애·삭제·덮어쓰기 실험을 하지 않는다. 원본 fixture의 전후 해시·크기·mtime·파일 생성/삭제 감시를 남긴다. 필수 bytes 손실/불필요 bytes 유입은 원본 계획/포함/제외 manifest와 실제 저장 파일을 대조한다.

Jest/React Testing Library/MSW·Playwright·실제 Next API/전용 MongoDB/SMB·파일 worker·등록 UE 환경을 제안한다. 현재 package.json에 runner/테스트 스크립트는 없으며 이번 작업에서 설치하지 않는다. OS·lockfile·Node·브라우저·DB·네트워크/권한·저장소 여유·정책/manifest·engine build/plugin/toolchain·검증 범위를 실행 증거로 기록한다.

사용자는 에디터에서 작업하고 영상·이미지만 출력했으며 별도 실행 프로그램을 만들지 않았다고 확인했다. 실행용 빌드의 보존·생성·실행 검증은 대상이 아니다. ‘영상·이미지 출력물 보존’과 ‘에디터에서 다시 열어 수정할 수 있는 프로젝트 복원’을 함께 검증한다. 필요한 Editor 모듈/plugin binary·Build 입력 보존과 별도 배포용 실행 프로그램을 혼동하지 않는다.

사용자가 재생성 가능한 파일만 제외한다고 확인했다. 따라서 UEF-07의 미사용 Content 보존은 확정 수용 조건이다. 현재 map에서 참조되지 않음·에셋 사용 횟수0·이름/용량만을 근거로 Content를 제외하는 구현은 실패로 판정한다. 원본 삭제나 자동 에셋 가지치기는 구현 범위가 아니다.

## 8 통합 시나리오와 단계별 게이트

**E2E-A / B1, 핵심 탐색·보존:** 제작 건→결과 영상+결과 이미지+FBX/소스 이미지/기타/UE 연결→dry-run·UE 예외 검토→별도 저장소 보존·checksum→방송연도 Netflix 카드→영상 재생/이미지 확대→소스 상세→원본 파일 다운로드·hash. 모든 소스 유형·역할·보존 상태 일치.

**E2E-B / B1, 이미지 단독:** 영상 없는 제작 건→제작 이미지/연결 소스 보존→제작 이미지 필터/연도 행→갤러리·설명/메모→원본/소스 다운로드→재조사. video endpoint 강제 호출/빈 동영상 오류 없음.

**E2E-C / B0, UE 최소 보존·복원:** source/C++·Content/Config/Build·binary-only plugin·외부 미디어·Saved 기능 자료·DDC/Intermediate/로그가 있는 표본→계획 포함/제외·review 해소→필수만 보존·원본 불변→원본/캐시 경로 차단→전체 보존본 다운로드·새 위치 복원/manifest 대조→정확한 환경에서 대표 map/Sequence·필요 Editor 모듈 재빌드. 불필요 캐시 보존0·필수 bytes 누락0, 실제 열기 증거 필요.

**E2E-D / B0, 장애·버전·백업:** 보존 중 단절/취소→부분 완료 차단→같은 key 재시도·검증→원본 v2/원본 offline→v1 자료 다운로드/복원→보존본 손상 탐지·백업 복구→v1/v2·정책·관계·bytes 대조. 원본/기존 보존본 자동 삭제0.

**E2E-E / B0, 권한:** 제한 사용자가 영상/이미지/소스/manifest/작업·다운로드 직접 접근→거절→계정 전환·늦은 응답/이전 job content 요청→누출0→허용 사용자 보존본 다운로드. 서비스 계정 NAS 권한이 사용자에게 승계되지 않음.

A단계에서 보존 목표/표본/환경·정책을 확정하고 B단계 CAT/SRC/VER/SEC 실패 사례부터 구현한다. C단계 PLAN/SAVE/UEF/DOWN의 정상·예외·장애를 먼저 검증하고 D단계 실제 복원·UE·백업·성능·E2E를 통과한다. 해당 단계 B0/B1은 모두 통과해야 하며 필수 데이터 손실/원본 변경/권한 누출/거짓 보존 완료0이 릴리스 게이트다.

선택 후속인 Fab 패키지·개별 에셋 자동 이행·AI·3D 뷰어 테스트는 현행 분모에서 제외한다. 이전89개/패키지 통과율을 이번 목표 달성률로 재사용하지 않는다. 실제 UE/SMB가 없으면 환경 차단/미실행이지 통과가 아니다. 환경별 지원은 실제 검증한 조합에 한하며 소수 표본으로 모든 프로젝트의 재편집을 보증하지 않는다.

## 9 결과·검증 상태

실행 결과는 요구/test ID·OS/도구/네트워크·실제 사용자/권한·source snapshot·policy/plan/manifest hash·포함/제외/review 파일 수/바이트·ArchiveVersion/checksum·job/lease/재시도·원본 전후 대조·download/restore hash·UE 환경/대표 map/실제 열기 결과·백업/복구 증거로 남긴다. 보존 verified·파생 ready·복원 passed를 별도 기록한다.

2026-10-29 v5.2는 제작 결과물·재편집 프로젝트 보존과 실행용 빌드 없음·별도 저장소·재생성 캐시만 제외한다는 답변을 반영한 **목표 테스트 설계**다. UE 보존 목표는 확정됐으며 실행용 빌드 부재를 누락/오류로 보지 않는다. 문서 구조·링크·요구 추적·핵심/후속 범위를 정적 점검하며 기능·DB/SMB·브라우저·실제UE·성능 테스트·의존성 설치·원본 조사·배포는 수행하지 않았다. 실행 사례는 모두 미실행이다.
